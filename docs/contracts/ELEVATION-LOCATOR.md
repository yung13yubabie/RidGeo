# Missing-elevation locator v1 — pure contract

Input is the existing validated `inspect_details` result for ORIGINAL bytes. Read `source.route_sha256` and `raw_profile_segments` by reference; no GPX parsing, new hashing, geographic computation, worker operation, model change, interpolation, mutation or network request. The caller owns the immutable original details reference and disposes this locator on a genuine route change/reset.

`createElevationLocator(details, {now?, yieldTask?, budgetMs=4})` returns:
- `summarize({signal?})`: complete `total_runs` and `missing_points` over all segments; no diagnostic objects retained. `complete:true` appears only on completed scan, never partial or truncated success.
- `page(cursor=null, {signal?})`: at most 25 `rows`, `first_ordinal` (1-based presentation), and `next` cursor or null. A cursor is an in-memory object tied to the locator instance AND original hash; fields record the segment index, next original segment point index, already accumulated segment offset and run ordinal. Foreign/reconstructed/other-session cursors reject; there is no input-controlled index lookup. Null always restarts. Pagination has no total finding cap and no successful silent truncation. UI separately displays the full summary and page range and provides previous/next controls.
- `dispose()`: future/current scans reject with `AbortError`; AbortSignal cancellation is also checked between points and after yield. No transport cancellation.

Rows are maximal consecutive `ele === null` runs within ONE original segment. All indices are zero based, all point ranges inclusive. A source index retains every duplicate and null original point, including separate runs at identical horizontal distance. `segment_index` is the array ordinal, matching the current Python profile contract. All the frozen Python missing-run fields are retained unchanged, including left/right same-segment original anchors, null absent anchors, affected adjacent edge envelope and null missing vertical difference. No coordinate/height is invented. `profile_horizontal_range_m` and `affected_profile_horizontal_range_m` add the sum of previous segments' EXISTING horizontal lengths, without connecting segments. These are original horizontal chainages, never canonical/derived pacing distances.

`raw_horizontal_range_m` localizes the missing points; the wider affected edge interval includes available same-segment anchors. A zero-width missing interval remains a source-index-identified point, not an empty finding. Missing endpoint and all-missing segments retain absent anchors as null. UI uses 1-based point labels and original layer only. All-missing profiles remain usable as a list and horizontal location marker, with no fake elevation curve or Y value.

Work is O(points) for summary and sequential page traversal. Retained auxiliary memory is O(25) records per returned page plus issued lightweight cursors; input points are neither copied nor serialized. Existing 50,000-point / 2,000-segment bounds are checked. The UI retains only the current 25 row DOM nodes and lightweight previous-page cursors. Scans check elapsed time every 128 point operations and yield using a macrotask after a nominal 4 ms work budget. This is a testable scheduling target, NOT a maximum task-duration or mobile-performance promise. Scheduler injection supports deterministic cancellation tests. Original details have already passed core finite-coordinate/elevation/chainage validation; this is not an independent untrusted GPX validator.

Frozen oracle: source-only route-quality diagnostics SHA256 e5f8d526dc773f2e59cbfb87c6ac633bdcda0cefe80d0a27263008bb6a010223, missing_elevation_runs only. The oracle's 10,000 all-diagnostics cap does not truncate locator pages; synthetic 25,000-run patterns must be checked independently when the oracle rejects that size.

## UI ownership and selected detail

The disclosure scans lazily on opening and explicitly shows total missing points / total runs plus current ordinal range. Closing cancels only that read-only scan. A selected row additionally reveals the original left/right anchor point index, original accumulated horizontal chainage and known height. These two lines are absent until selection, not another persistent explanatory paragraph. Source changes invalidate rows, cursors and selected marker; same-source repair does not transfer those indices to derived geometry. Viewing from a derived chart switches to original before marking. No plan/CP/settings invalidation or transport cancellation is permitted for these view actions.
