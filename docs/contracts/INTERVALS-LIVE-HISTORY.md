# Intervals live-history private path (R14)

## Delivery and trust boundary

The default same-origin routes return 503 until a trusted host origin, server-side verified-session resolver, and explicitly reviewed source policy are supplied. Browser controls accept dates and opaque selection handles, never API keys, bearer tokens, session fields, or normalized JSON uploads. An injectable private synthetic session/fixed-provider transport exercises context → list → import → single/multiple selection → protected Worker/WASM prediction → exact original owner-held workout capability. This is a complete private software path, not an activated account service.

The server always revalidates the owner before data reads and at stream checkpoints/completion. Context calls do not refetch activity streams. Incomplete/failed streams are never admitted as usable receipts. Access binding returned to the browser is minimal opaque metadata, not principal/session/token details. Platform identity is not proof that two uploads represent distinct real-world activities: selected multiple histories require explicit distinct-activity confirmation.

## Exact input and prediction

The provider input family is distinct from LocalGPX. It retains exact normalized response text/hash and independent source-body snapshot evidence. Fractional moving/elapsed clocks remain exact, readonly source observations; missing/invalid source clocks cannot be repaired with UI overrides. Completion date, actual activity, comparable conditions, whole-route scope, high effort, reference kind and distinct activity are explicit user qualification. Classification changes preserve original/import selection/current override separately and never rewrite or refetch the admitted response.

Selection IDs and selected activity indices are unique. Repeated aliases for the same stable activity remain one weight with conservative resource charges. Identical geometry for different platform IDs is not byte-deduplicated. Subset eligibility/overlap is recomputed from selected activities; unselected limited/overlapping rows remain inspectable without affecting a qualified subset.

A separately pinned provider adapter replays every normalized sample/segment/index and exact cross-language domain-separated hashes before producing an internal GPX geometry carrier. Carrier labels stay Intervals-derived, not original LocalGPX. No decimation, gap filling, timestamp fabrication, elevation repair or distance rescaling occurs. Numerical core, existing local single/multi and hybrid methods are unchanged. Multiple provider activity rates use equal mean effective rate, not mean duration. Protected result and plan carry mandatory source kind.

## Currentness, export and errors

The app retains the original private wrapper/receipt/request/owner/correlation. Bare tagged plans, cloned wrappers, silent target or qualification changes, stale generation, cancel and expiry cannot obtain an export capability. Repeated rendering/getters do no upstream requests. Opening/rebuilding/copying/downloading a provider workout or prediction JSON asynchronously rechecks access, then rechecks exact current wrapper/target/global/evidence/generation immediately before write. A changed account/grant/policy clears provider data/results while retaining local history and target. Transient 429/timeout/unknown access refuses that action and retires derived results while keeping blocked sealed observations; it never falls back to cached authorization.

API-list/import, provider Worker and other app work have separate ownership. Late aborted responses are canceled and stale callbacks cannot retire newer goal/manual/local work. Only an admission rejection bound to the exact current target SHA and dispatch receipt can retire that target. New provider errors use stable codes with concise Chinese messages and relevant control IDs. Workout failures now use bounded short Chinese messages with optional current CP-occurrence focus. Converter error codes, quantization, source data and ownership rules are unchanged; actual browser focus behavior remains a separate qualification.

## Bounded resources and unresolved support

Accepted caps remain unchanged: 72-hour elapsed/duration bounds, 50,000 samples/path points, 500 km source bounds; normalized response16 MiB/1.5m nodes; provider request32 MiB with the exact response inside one string and10k outer nodes; owner128KiB/50k nodes; derived GPX5MiB each and12MiB alias-charged aggregate including target; target15k cells and total100k cells; CP100; result16MiB/1m nodes;120s initialization+wrapper wall time. These are unresolved ultra-history support limits, not coverage promises: 50k native1Hz samples span only13h53m19s. No support expansion is claimed.

The client uses one128MiB/4.5m-node representation ledger covering staged/retained response text and parsed data separately, carrier/base64/request/owner, hash/replay/receipt, workout/text/blob export allocations and releases; inactive local retention has its separate bounded charge. Reservations precede the charged allocations and scoped parse leases stay live through the caller's final use. Representation accounting is not a heap-safety guarantee.

The wrapper streams the already normalized trusted inner JSON bytes into a fixed envelope, removing a redundant full-text/parse/stringify copy; it enforces16MiB before enqueue and retains the acquisition lock through completion/cancel/15s deadline. The accepted inner handler retains only bounded listing observations, at most4MiB/250k nodes including staged plus retained entries,4000 choices/32 sessions. Wrapper context metadata is at most32 entries×4KiB. It does not retain normalized activity paths. Aggregate cache plus in-flight peak is distinct from wire size. Native Node measurements are research evidence, not a Cloudflare128MB-isolate acceptance; full-cache concurrent normalization and actual Cloudflare memory acceptance remain blockers.

## Activation blockers

No credentials, OAuth grants, external account calls, hosted service activation or publication occurred. Real-account/source-rights approval, supported host identity/session integration, real Cloudflare peak-memory qualification, native browser acceptance and expanded ultra-distance/history scope remain open. Preserve LocalGPX as a working alternative and refuse overlimits without silently truncating or reconstructing data.
