# Accepted station-clock workout text

R18 extends the existing local distance/moving-pace dialog to an accepted complete
station-clock comparison, including manual pace edits retained in that family.
The app's current A owner must issue an opaque object-identity source capability.
Purpose/status/current:true, cloned plans, copied token-shaped objects and the
separate station JSON export cannot grant this authority. A token is tied to its
original plan object, private complete composite request and current owner head,
route/raw-input signature, content and transaction generation. The module-private
registry is a boundary against data/JSON substitution, not arbitrary privileged
JavaScript invoking the trusted issuer itself.

Issuance and conversion rebuild the complete composite ledger with the existing
validator, including verified native manual proof where present. The private
request, GPX and source proof remain private; text, preview, result_basis and
checkpoint metadata contain none of them. Current-owner admission precedes terrain
allocation. This retains station admission's existing 8 MiB/500000-node plain-data
preflight and 101-CP limit, not the selected-history 15000-cell cap. Terrain/step
counts are derived from that admitted ledger; no device step ceiling or truncation
is introduced. Ordinary goal/manual/history conversion remains unchanged.

Both omit and planned-duration station output use intervals-distance-workout/1.1.
Movement targets use only the accepted canonical/CP movement ledger. Omit excludes
all accepted total dwell; planned-duration reuses the existing cumulative whole-
second stop conversion. Service/rest components are declarations, never extra
steps added on top of total dwell. Exact source meters, movement, total dwell,
arrival/departure and revised finish remain unchanged. The source's initial goal
is disclosed; it is not rebalanced by the exporter.

Repeated names are display text. Exact station occurrence IDs come from the
validated clock ledger; a real user-added finish retains its ID, while the app's
reserved automatic-finish has null ID. Zero-dwell interior CPs remain boundaries.
Positive dwell that quantizes to zero or a zero CP absorbing rounding residue
refuses the complete optional timed export under the existing policy. Its exact
occurrence can focus the unchanged raw CP stop control; movement-only export is
still available. An unknown draft cannot create a new accepted clock plan.

Busy transactions/barriers prevent conversion and cached copy/download. A new
transaction, cancel, Apply, Undo, Exit or observed source/route/raw-CP change revokes
cached capability identity; edit-and-revert cannot resurrect it. A detached,
unapplied or canceled draft may leave the accepted head intact. Reopening the
dialog obtains fresh authority for that accepted ledger and never adopts draft
values. Complete Undo/Exit selects the corresponding accepted or original plan.

The dialog and result basis explicitly describe a clock-only account: fatigue
response, recovery benefit and personally optimal rest are not estimated. The
local parser roundtrip and software conservation checks make no claim of actual
Intervals server parsing, watch transfer, navigation/arrival triggers, stationary
rest execution, T-Rex 3 compatibility, empirical accuracy or confirmed step limits.
