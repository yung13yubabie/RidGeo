# Local history workout export and planned CP duration

This extends the existing local text dialog. True multi uses the admitted equal-weight
mean-effective-rate target timeline, with provisional calibration and unverified external
activity identity. It does not average finish predictions or identify fatigue/recovery.

Every selected-history app wrapper, including aliases collapsing to one unique record,
requires its original private receipt/request/correlation context and current owner.
The converter requires exact original receipt-child object identity, then invokes the
existing complete selected-history validator. Matching status/hash/current:true alone
cannot enable true multi. Private request/owner bytes and GPX never enter workout output.
The getter checks unchanged selected records, visible active evidence even when unselected,
global controls, current date/start, raw CP occurrence/control capture, target bytes,
route/provenance and exact installed wrapper/receipt/plan. View-only active switching is
allowed. Copy/download reuse immutable conversion only after current identity checks.

stopMode defaults to omit. Existing legal goal/manual/singleton/hybrid movement-only output
keeps intervals-distance-workout/1.0 unchanged. True multi or planned-duration output uses
1.1, discriminated movement/planned_stop steps and exact copied checkpoint metadata.
Preceding movement and planned stop indexes are executable one-based indexes;
movement_index is the separate movement-only ordinal. Requested station IDs are derived
from bound raw owner controls and ordered canonical occurrences. Generated finish has no
invented ID. Repeated station names are display data, never identity or grammar.

Optional positive CP dwell becomes a duration-only line of the generated subset:

    - CP stop A 75s intensity=rest

The ordinal is generated from source occurrence order. Source names never enter executable
text. Zero dwell creates no duration step; interior zero CP remains a movement boundary
and controlled following prompt. Positive finish/unlocated dwell remain refused. The
rest intensity is a classification, not a recovery model, CP navigation trigger, stationary
execution or lap-button wait. Downstream formatters can omit duration-only untargeted rest.

Exact source meters/seconds/arrival/departure are preserved in memory. Export uses conserved
cumulative whole-meter distance, whole-second/km movement targets and cumulative whole-second
stops. A positive source dwell rounding to zero, or a zero occurrence absorbing a residual,
refuses the entire optional timed output. Default movement-only remains available. Independent
round(moving)+round(stops) need not equal round(elapsed); totals expose this difference and
nominal pace/distance-derived duration separately. Source metadata clones preserve -0 in
memory; JSON text itself cannot encode negative zero. No rounding modifies the source plan.

Selected target counts retain 15000 cells,100 requested CPs and at most one generated finish.
Preflight applies before terrain allocation. These are software admission counts, not watch
step ceilings. All generated steps stay present; no truncation or implicit merge occurs.
Ordinary legacy exports receive no new resource cap.

Syntax is a documented local subset with a local exact roundtrip. Real Intervals server
parsing, Zepp formatting, T-Rex 3 execution and step limits remain unverified. No device
compatibility claim follows from producing/copying/downloading text. Account/full-stream
integration and automatic best-rest remain separate open requirements.

Canonical station names follow the existing receipt validator's Python-compatible strip of
the requested name. Raw DOM JavaScript trim must still match the exact request name.
Occurrence mapping uses that already-validated ordered name binding plus exact distance/stop;
the converter copies the canonical source name unchanged and does not run another strip.
